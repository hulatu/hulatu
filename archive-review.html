归档页改造评审

去掉三处重复，让日期成一条轨道

hulatu.com/archive/ · 2026-10-02 · 参考 hugo-bearneo + getdesign.md
已实施（2026-10-02）：P0 全部 + P1 全部 + P2 的「单月年份不出月份标签」。 月份按你的决定不再折叠。未做：年份 sticky 吸顶与锚点、月名改中文数字 —— 这两条留着，哪天想动再说。
杂乱不是「元素太多」，是同一件事说了三遍：篇数说两遍（年、月）， 月份说两遍（分组标题、每条日期），折叠控件也给两遍（年一个箭头、月一个箭头）。

一、诊断

现在的归档是「时间轴 + 年 + 月 + 条目」四层。每一层都想有存在感，于是同一屏里挤了这些东西：

三个重复

  • 篇数重复：年报一次「110 篇」，下面每个月的标题又各报一次。展开后你其实可以直接数出来。
  • 月份重复：分组标题已经写了「12月」，每条文章前面又写「12-05」—— 同一个月在一行里出现两次。
  • 折叠控件重复：年和月各有一个 chevron，一屏里竖着排两列三角。

两条打架的线

  • 左边一条 2px 时间轴竖线，上面挂着两种标记：年的 12px 空心圆环、月的 6px 实心点。
  • 月份之间还有一条 1px 虚线分隔。
  • 竖线（纵向）+ 虚线（横向）+ 两种圆点，是四套不同的「线/点」语言同时出现 —— 这就是「乱」的直接来源。
一个极端的例子：2025 年只有「12月」一个月。 于是那里渲染出「2025 · 12 篇」紧接着「12月 · 12 篇」—— 两个数字一模一样， 年份下面只有一个月份标题，月份标题没有提供任何信息。11 个月标题里，至少有几个是这种情况。

改造后具体做了什么

  • 月份标题退成一条安静的标签：去掉计数、去掉箭头、去掉圆点，只剩「10 月」这行小字（等宽 + 字距）。月份不再是折叠单元。
  • 条目日期只留「日」：10-01 → 01，月份交给上面的标签。日期列固定宽度，几百行对齐成一条左轨。
  • 篇数只留一级：删掉月级计数，年计数靠右（margin-left:auto），不再紧贴在年号旁边。
  • 年份下面加一条横线：替代原来那条纵向时间轴。账本的语言是横线，不是时间轴。
  • 去掉月份之间的虚线：分隔交给留白。
  • 行高松绑：条目上下 padding 从 8px 提到 11–12px。

三、bearneo 是怎么做的

我把 rokcso/hugo-bearneo 的归档实现拉下来看了 —— 它的归档页只有这些：

  • layouts/_default/list.html：一个平铺的 <ul class="blog-posts">，年份是个光秃秃的 <h3>，每条 <li> 是「日期 + 标题」。
  • CSS 只有三条相关规则：li { display: flex }、日期 span { flex: 0 0 80px }（固定宽度列）、time { font-family: monospace }。
  • 没有月份分组、没有篇数、没有时间轴、没有折叠、没有分隔线。

也就是说 bearneo 的「结构」只有两样东西：一个等宽的日期列，和年份标题。 它靠一条对齐的日期左轨把几百行收干净。你的日期列其实也是对齐的（日期都是等长的 MM-DD， 又是等宽数字），真正的问题是：这条轨道每过几行就被一个 4 元素的月份标题打断一次， 再加上左侧那条挂着两种圆点的竖线 —— 轨道感因此没建立起来。

可直接借的一条：把日期列宽度写死（flex: 0 0 2.2ch）， 而不是只写 flex-shrink: 0。你现在能对齐，是因为所有日期都恰好是等长的 MM-DD —— 属于「碰巧对齐」。改成「只显示日」之后列宽变成 2 字符，这时更该把宽度锁死： 以后不管换成 01、01-02 还是 Jan 2，标题的起始位置都不会动。

要保留的

年份可折叠（长列表里最自然的折叠单位，保留）；月份分组本身（122 篇 / 11 个月，分组确实有用，只是它不该再占一整行 chrome）； .archive-total 那行「共 122 篇 · 今年写了 N 字」（它是全页唯一的汇总，留着）； 衬线年号 + 等宽数字的分工（--font-serif / --font-meta，这套是对的）。

需要你定的一件事

月份要不要保留折叠？我倾向不保留 —— 月份退成标签后，折叠单位只剩「年」， 一屏里就只有一列箭头了。但如果你觉得 8 月那 23 篇展开后太长，也可以保留月份的折叠， 只是那样就得接受多一列箭头。这个改动会明显影响观感，动手前想听你一句。
