极简已经走到底了，剩下的是手艺

你问的是「站在极简主义、借鉴 Apple / Google 的审美，还有哪些地方可以改进」。 我先按技能要求跑了五个量化扫描，结论是「还能删的东西基本没有了」： 刻度外值只剩 3 处、空章节 0 个、死 token 0 个、卡片三件套已清、对比度全过 AA。

所以这一页报的不是「哪里还不够简」，而是三类手艺问题： 一套名字比值多的圆角 token、一套做了八次却没做完的触控命中区、 以及两套并行的字号尺度。这三件事在 Apple / Google 的系统里都有明确答案， 而它们恰好都不在「装饰」那一类 —— 所以不违反你写在 DESIGN.md 里的 「要收敛的是装饰，不是能力」。

02触控命中区：做了八次，没做完，而且标准在飘

这个站有一套很好用的手法：视觉尺寸不变，用 ::after / ::before 加一个 负 inset 把可点范围撑大。它已经用了 8 次。但把 14 个交互目标的 有效命中区全量算出来之后，会看到两件事：标准从 29.2px 飘到 60px， 以及最该有它的几个元素漏了。

也不是截图。每个条的长度就是它真实的命中区宽度（1 单位 = 1px）。 「视觉尺寸不变、只放大可点范围」这件事本站已经做过 8 次，值都从 CSS 里读出来复算： .nav-icon-btn 44 + inset:-8px×2 = 60（critical.css:706+:714）； .site-brand 30 + inset:-10px×2 = 50（critical.css:739，注释自己写着「够到 WCAG 2.5.5 的 44」）； .tag-chip 11.52×1.7 + 0.32em×2 = 26.95，再 +8×2 = 42.95（critical-page.css）； .footer-links a 24 + 4×2 = 32（critical.css:749）； .post-cat-chip 11.52×1.4 + 0.22em×2 = 21.2，再 +4×2 = 29.2（critical-post.css:1026）。 下面 6 个没有任何扩展器，长度就是它们自己算出来的高度。 带 ~ 的两个（.code-block-copy / .year-chip）没有声明 line-height， 按继承的 1.8 估算 —— 这是本页唯一两处估算值，其余全部来自显式声明。

为什么这条算「手艺」而不是「功能」：站内注释同时引用了两套标准 —— critical.css:739 写「够到 WCAG 2.5.5 的 44」，:726 写「正好压在 WCAG 2.5.8 的线上（24）」。 所以并不是「标准太低」，而是同一套手法没有统一的目标值。 Apple HIG 是 44×44pt、Material 是 48×48dp —— 两个都远高于 WCAG 的 24 最低线， 而本站已经有一半元素够到 44 了。

05明确该留的（不要动）

DESIGN.md 的 Don't 末条是明文：「不要为了极简删掉功能。搜索、目录、灯箱、周刊、打赏、评论都是保留项； 要收敛的是装饰，不是能力。」下面这些我一个字都不建议改 —— 其中有几条是本站在 Apple / Google 之上的地方：

  • 发丝线承担层级（--line + --surface-2，全站零卡片零投影）—— Apple 用毛玻璃、Google 用 elevation 阴影，本站比两者都更克制。这是身份，不是落后。
  • 一个印章红，且稀缺 —— 两个大厂都做不到只用一支强调色。
  • 680px / 17px / 1.8 的阅读节奏 —— 中文密排需要这个呼吸，别为了「紧凑」压。
  • 命中区扩展器这套手法本身 —— 思路完全正确（Apple 的「视觉尺寸 ≠ 可点尺寸」）， 这一轮报的只是「没做完 + 没统一」，不是「做法错了」。
  • 孤行保护（orphan-safe.html，末 2 字包 nowrap）—— 从 Apple 中文站搬来的，已落地。
  • text-autospace: normal —— 同上，中英自动空距已落地。
  • 文章标题不做 text-wrap: balance —— 这条是对的， 中文开 balance 会让每一条多行标题的第一行都短一截。
  • 三档断点（1152 / 760 / 600） —— 别改成流体 clamp() 铺满全站； 现在只有 .hero-line 和 .notfound-code 两处用 clamp，是正当的例外。
  • 卡片三件套那 26 处 —— 逐条看过，全是胶囊 / 键帽 / 代码块 / 浮层，没有一处是装饰卡。
