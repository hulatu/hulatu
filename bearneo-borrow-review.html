四、如果做 content-visibility，有一个坑必须先知道

bearneo 是直接挂在 img 上的。你照做没问题，但千万别顺手扩到 .post-content > *：

原因。content-visibility: auto 会给元素加上 size containment —— 被跳过的子树，浏览器会按「假尺寸」算布局。而你 toc.js 的滚动高亮、以及 initHashAnchor() 的「带 #锚点 进页面后重新对准」， 都依赖 getBoundingClientRect().top 去判断「现在读到哪一节」。 挂在 .post-content > * 上，这些标题就会拿到被压过的假值， 目录高亮会乱跳、锚点会对不准。挂在图片 / figure 上则完全安全，因为图片不在目录的测量链路上。

另外两个次要提醒：你 critical-post.css 里有 .js .article-image img { opacity: 0 } → .is-loaded { opacity: 1 } 的淡入。逻辑本身是稳的（ui.js 先判 img.complete && img.naturalWidth > 0，不会出现「加载完了但 class 没加上、图永远透明」）， 但加 content-visibility 之后值得把图片多的几篇（第四期 19 张、第十期 21 张、开封一日游 17 张） 实际滚一遍确认。

五、P1 详解：中文斜体的那个坑

bearneo 的 style.html 里有一条很不起眼、但很懂中文排版的规则：

i { font-style: normal; }

它为什么要专门把 <i> 掰正？因为它的列表模板把日期包在 <i> 里， 而中文没有真正的斜体字重 —— 浏览器会拿正体做「合成斜体」（把字形沿一个角度切变）， 出来的效果是字歪着、笔画变形，很难看。

你这边的情况是：CSS 里一处 font-style: italic 都没有（除了代码高亮里给注释用的那一条）， 所以目前没有任何地方在斜。但反过来说，你也没有兜底 —— Markdown 里写 *强调* 会渲染成 <em>，走浏览器默认的斜体。全站有 30 篇左右的文章里出现过 单星号（也可能全是 **加粗**，我这边没法只靠正则区分）。

建议。先花一分钟确认一下：随便打开一篇，看正文里有没有中文被显示成歪的。 如果有，就按 bearneo 的思路处理 —— 但不是照抄 i { font-style: normal } （那是无差别掰正，连英文的 <i> 也一起管了），而是给 .post-content em 单独定一套： font-style: normal + 用印章红的波浪下划线或加粗来承担「强调」的语义。 这比斜体更贴你「纸账 + 印章」的调性，也顺手把全站最后一块「不是自己定的样式」收进来了。 如果没有，就在 MAINTENANCE.md 记一笔「中文不用斜体，要强调用加粗」， 免得以后忘了这个坑。
