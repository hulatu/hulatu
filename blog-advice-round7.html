一、设计层面（美化）

1.1 深色浮层层次 P0

搜索面板和灯箱在深色模式下的浮层浮不起来。

问题：深色页面底 --paper:#0b0b10 的 CIE 明度 L* 只有 3.14， 所以遮罩再黑也只能把页面压暗 3 点。当前遮罩 rgba(20,22,26,.42) 的 RGB 比页面还亮， 实际效果是把页面提亮 +1.58；面板又用 --paper（与页面完全同色）， 于是比遮罩还暗 −1.58，视觉上凹进去。

建议：深色下遮罩改 rgba(0,0,0,.62)、面板改 --surface， 面板 vs 遮罩可提升 ΔL* 到 +9.25。浅色保持原值不变。

涉及文件：assets/css/critical.css（遮罩 token）+ core.css（面板底色）

1.2 标签页视觉层次 已修

2026-09-29 已按文章数量给标签分 tag-chip-lg/md/sm 三档，7/21/138 个胶囊分别拿到不同字号 + 透明度。 当前状态正常，无需再动。

1.3 中文排版：孤字问题 P1

长标题在 680px 容器内换行时，末行容易只剩 1 个字。这不是 bug，是中文排版的必然。 但不要用 text-wrap: balance/pretty 来治——它们在中文里会让行提前换行， 正是用户之前抱怨的「断开的地方没到最右端」。

建议：给出「全站 N 条长标题里 M 条末行 ≤2 字」的清单，让用户自己决定要不要改文案。 改文案（加/减几个字）比改 CSS 有效得多。

MAINTENANCE 明确反对造新词：「>60% 的碎片率就是造新词」。当前 70.6% 远超阈值。

建议：清理只用 1 次的标签，把它们合并到已有标签或删除。 例：如果有一篇打了「读书笔记」但只有 1 篇，可以合并到「阅读」或「写作」。

同样的问题在分类：「现象」「分享」「情绪」各只有 1 篇， 可以考虑合并到「记录」或「思考」。

2.2 分类与标签重复 P1

检查是否有同一个词既当分类又当标签。例如「情绪」既是分类（1 篇）又是标签（若干篇）， 会造成两个term页内容几乎相同，对 SEO 不友好。

三、交互层面（体验）

3.1 页头图标按钮偏小 P1

页头四个圆形图标按钮（搜索/主题/RSS/汉堡）是 34×34 px， 在 WCAG 2.5.8（AA）的 24×24 边缘通过，但距离 Apple HIG 的 44×44 和 Material 的 48×48 有差距。 手机上点起来不够爽快。

建议：加到 40×40 或 44×44，同时调整页头高度和间距保持视觉平衡。 文件：assets/css/critical.css（.nav-icon-btn 尺寸）

3.2 灯箱缺少 touch 手势 P1

lightbox.js 没有 touch 手势，手机上换图只能点两侧箭头（≤600px 时箭头距边 8px，会压住图片边缘约 16px）。

建议：添加左右滑动手势切换图片，提升移动端体验。 文件：assets/js/lightbox.js

3.3 标题锚点在触屏上隐形但仍可点 P2

.heading-anchor { opacity: 0 } 只靠 :hover / :focus-within 显形。 触屏上没有 hover，锚点隐形但仍可点（opacity:0 不移除命中测试）， 点标题末尾会莫名弹「链接已复制」。全站没有任何 hover: none / pointer: coarse 查询。

建议：@media (hover: none) { .heading-anchor { opacity: 1 } } 文件：assets/css/critical-post.css

3.4 移动端菜单「点空白处不关」已修

2026-09-30 已修复：点菜单/汉堡以外的任何地方都会收起。当前正常。

四、性能层面（加载）

4.1 长文章滚动性能 P1

长文章（如周刊）有大量图片和代码块，滚动时浏览器要渲染全部内容。

建议：给图片加 content-visibility: auto，让视口外的图片跳过渲染。 ⚠️ 只能挂在图片 / figure 上，绝不能挂 .post-content > *—— 因为 toc.js 的滚动高亮和锚点定位都依赖 getBoundingClientRect().top， size containment 会让这些计算失真。

文件：assets/css/critical-post.css（.article-image）

4.2 搜索索引体积 P2

search-index.json 224 KB（122 篇文章，平均每篇 1.8 KB）。 当前 Fuse.js 搜索是点开搜索面板时才 fetch，不影响首屏。但如果文章继续增长， 可以考虑只索引标题/标签/摘要，正文用摘要替代——能省 60–80%。

4.3 首屏字节 优秀

当前各页型首屏 gzip 4.8–8.5 KB，0 个阻塞资源， JS 单包 5.2 KB gzip defer，已经非常优秀。无需优化。

六、需要拍板的问题

Q1：深色浮层层次要修吗？
涉及搜索面板、灯箱、移动菜单三个浮层在深色模式下的遮罩/面板配色调整。 改动面不大（几个 token + 面板底色），但会让深色模式的浮层体验明显提升。
Q2：标签碎片化要清理吗？
170 个标签里 120 个只用 1 次。清理需要手动判断每个「孤儿标签」该合并到哪个已有标签， 还是直接删除。这是个内容决策，不是技术决策。
Q3：页头图标按钮要加大吗？
从 34×34 加到 40×40 或 44×44，移动端点起来更爽快，但页头整体高度和间距要跟着调。
