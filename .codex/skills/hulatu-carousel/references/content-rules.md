# 内容提炼规则

把长文转成图文时的取舍标准。规则优先于任何「生成更多页」的冲动。

## 提取

从文章里提取：

- 中心思想
- 最强的开场 hook（具体场景、时间、生理感受优先）
- 个人经历
- 3–5 个最有力的论点
- 结论（原文怎么说就怎么说）

忽略：Hugo front matter 的无关字段、目录、图片/代码、打赏与评论模块。

## 页结构（默认 8 页，允许 6–10 页）

| 页码 | 版式 | 内容 |
| --- | --- | --- |
| 01 | cover | 标题改写为 10–18 字 + 一句副题 |
| 02 | content | 开场：原文最具体的细节，制造共鸣 |
| 03–06 | content/list | 每个核心观点一页 |
| 07 | content/quote | 结论，不鸡汤、不夸大 |
| 08 | cta | 关注引导 |

页数按文章信息量调整：内容少就 6–7 页，多就 9–10 页；不要为了凑 8 页加空页。

## 文案规范

- 正文每页 30–80 字；标题 ≤ 18 字，两行以内
- list 条目每条约 20 字，共 3–4 条，条目之间是并列关系
- 保留原文用词与语气：第一人称、坦诚、克制
- 允许适度压缩，不允许改变原意；引用只能来自原文
- 禁止：emoji、网络梗、夸张标点（如 `！！！`）、虚构引用、点击诱导、情绪勒索式 CTA

## manifest.json 字段

render 脚本的输入，数组形式，每页一个对象：

| 字段 | 适用 type | 说明 |
| --- | --- | --- |
| `type` | 全部 | `cover` / `content` / `list` / `quote` / `cta` |
| `title` | cover/content/list/cta | 页标题，≤ 18 字 |
| `body` | content/quote | 正文；支持 `<p>`、`<strong>`，其余一律转义 |
| `items` | list | 字符串数组，3–4 条 |
| `kicker` | 全部 | 顶部栏文字，如 `01 / 核心观点` |
| `tag` | cover | 标签，如 `开学季` |
| `subtitle` | cover | 一句副题 |
| `meta` | cover | 底部信息，如 `2026-09-01 · hulatu.com` |
| `src` | quote | 引用署名 |
| `file` | 全部 | 输出文件名；缺省为 `NN-name.png` |

## 交付文件

- `carousel.md`：逐页完整文案，供发布前人工检查
- `caption.md`：抖音文案（首行即钩子）、3 个标题建议（各 ≤ 30 字）、3–6 个话题
- `manifest.json`：与 PNG 一一对应，勿留孤儿页
