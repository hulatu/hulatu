01复算：装置铺得有多宽

全站构建产物 345 个 HTML。其中真正的长文页是 125 个（文章 101 + 周刊 24）。剩下的 220 个页面是首页、分页、分类、标签、归档、关于、装备、制作说明、隐私、书影音、结算、友链、404 —— 这些页面大多一屏到底。

装置出现的页面占比真正需要它
.reading-progress 阅读进度条34399.4%125
#back-top 返回顶部34399.4%125
.skip-link 跳到主内容34399.4%345

两者都来自 layouts/_default/baseof.html 第 109 / 118 行，无条件渲染。也就是说有 218 个页面挂着两个永远用不上的装置：在 6KB 的首页上，进度条要么停在 0%、要么在你按下滚轮的一瞬间就满格；返回顶部按钮则在页面本来就不需要滚动时出现在右下角。

注意 DESIGN.md 的 P2-7 只说「阅读进度条同样保留（红可以留，但常驻元素压到 2px，越细越像墨线）」—— 它定的是粗细，从没说过要挂在每一页。这条收窄不违反任何已拍板的决定。

02并排一：一篇文章页上站着几个「定位装置」

长文需要「我在哪」的辅助，这没问题。问题是这个需求被六个装置分别回答了一遍。

这不是截图。左边每个方块都按真实尺寸复刻：进度条 2px / background:var(--accent)（critical.css:385）；右栏目录面板宽 clamp(212px, 50vw - 372px, 244px)、≥1152px 才出现（critical-post.css）；图钉 13px 圆、绝对定位在目录框左上角；.resume 是正文顶端一条 22px 高的提示条；.back-top 42×42 圆、border-radius:50%（critical.css）。

为什么先砍这两个：图钉（#toc-pin）解决的是「悬停才展开的目录想让它常驻」—— 但同一件事右栏目录的 :hover 已经做了，多一个需要学习的按钮换来的只是「少悬停一次」。阅读位置条（.resume，2026-10-07 新增）只在「第二次访问同一篇长文」时出现，触发条件窄、代码却不小（localStorage + 三态 + 预渲染闸门），是典型的出现率远低于实现成本的装置。

也不是截图。左边是 /tmp 里构建产物的逐格真实数据：2026 年 1–10 月是 34 / 16 / 7 / 7 / 3 / 1 / 3 / 23 / 15 / 4 篇，11、12 月无内容；2025 年只有 12 月有 12 篇。四档色阶照抄 critical-info.css 的 color-mix(in srgb, var(--accent) 18% / 40% / 62%, var(--paper)) 与 var(--accent)。格子 34px 高、border-radius:5px、gap:4px。

04页脚的密度：比主导航还大一倍

主导航 4 项（关于 / 归档 / 周刊 / 分类）。页脚 8 条（花园 / 友链 / 标签 / 书影音 / 统计 / 开往 / 隐私 / 邮箱）再加一条 CC 协议行。MAINTENANCE.md 给页脚的定义是「全站栏目索引的兜底出口」，理由是 /tags/ /media/ /stats/ 在导航里没位置 —— 这一条成立，但另外三条不属于「栏目索引」：
