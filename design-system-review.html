Design System Review · 2026-10-31

设计规范系统评审

在现有 Bear Neo 风格不变的前提下，把「逐处手写的像素」收成一套可复用的尺度 —— 这是这个站距离「现代、专业」最缺的那一层。

先说结论。你的站不丑，也不土。它的问题不是审美，是没有系统： 29 种字号、23 种内边距，全部是每次遇到新组件时临时挑的数字。

专业设计系统最显著的标志恰恰相反 —— 有限的几个值，被反复使用。 下面所有判断都能在 themes/hugo-bearneo/layouts/partials/style.html 与 layouts/partials/custom_head.html 里查到出处，计算样式由真实浏览器量取。

  • 29种 font-size
  • 23种 padding
  • 13个字号挤在 3.7px 区间内
  • 7个可修的层级缺口

一、诊断：字号长尾

把全站所有 font-size 按大小排开，会看到一条典型的「长尾」—— 13 个值堆在 11.5–15.2px 之间，其中还有两组是完全相同的值（0.8em 与 0.8rem 都是 12.8px，0.9em 与 0.9rem 都是 14.4px）。

13 个值
16 20 24 32 54

红色区间 = 13 个「元信息字号」，全部挤在左侧 8.5% 的宽度里； 灰色是正文与标题字号，彼此分得很开。
红区内这 13 个值依次是：11.5 / 12.0 / 12.5 / 12.8 / 12.8 / 13.1 / 13.6 / 14.4 / 14.4 / 14.7 / 14.7 / 15.2 / 15.2（单位 px）。 其中 12.8、14.4、15.2 各出现两次 —— 0.8em 与 0.8rem 是同一个 12.8px，写了两种。 它们在屏幕上实际只分得出 4 个档位，但维护成本是 13 份。

「同一事物，两种值」的三个实例

同一件事值 A值 B出处
正文行高 1.8 1.5 文章 content / 首页 main
正文段间距 28px 16px 文章 content > p / 首页 main > p
横向内边距 12px 14px / 16px / 20px 按钮、标签、卡片各一套

第一条是本次最值得修的一处，单独展开。

二、七个发现

P0首页正文是「次级排版」，行距比文章页紧 20%

首页 main > p font-size:16px line-height:24px (1.5) margin:16px 0 文章 content > p font-size:16px line-height:28.8px (1.8) margin:16px 0 28px

原因：行高与段间距都写在 content 选择器上，而首页的简介在 <main> 里、不在 <content> 里。

你自己在 style.html 里给 1.8 写的理由是「中文是方块字、没有 x-height，1.6 读长文明显更挤」—— 这条理由对全站第一段文字同样成立，但它没生效。视觉结果就是首页四段话挤成一坨。

修法：把行高与段间距的规则从 content 提升到 main（或两条都写）。 一行改动，影响 379 页里的每一页首屏。

P0文章页出现两个 32px/700 的标题，品牌与内容同级

站名 font-size:32px font-weight:700 文章标题 font-size:32px font-weight:700 ← 完全相同的视觉权重

读者进入文章页，先看到「胡拉图说」，隔两行又看到一篇同尺寸的粗体标题。 两者没有任何视觉手段区分「我在哪个站」和「这篇讲什么」。

现代博客的通行做法是站名小、内容大：站名 20–24px 作为品牌锚点， 文章标题 32px 以上作为页面主体。你现在的站名是全站最大的东西，等于把「品牌」摆在了「内容」前面。

P1标题继承了正文的 1.8 行高，多行标题会散架

正文 h2 font-size:24px line-height:43.2px (=1.8) 正文 h1 font-size:32px line-height:48px (=1.5)

DESIGN.md 第 3 节其实已经记过这件事：「content 是唯一带行高的容器规则， 所以标题也继承这 1.8（标题单行时看不出差别）」。已知，但没修。

单行标题看不出来，一旦 h2 折成两行，行间就会出现 19px 的空隙， 标题读起来像两段独立的话。标题的行高应该在 1.2–1.35。

P1引用块：4px 粗边 + 8px 内边距，文字贴着边线

blockquote border-left: 4px solid #d0d7de padding-left: 8px

4px 的边线在 16px 字号旁显得很重，而 8px 的内边距又让文字几乎贴上去 —— 一重一轻，比例失衡。 这是全站唯一一处「装饰性线条」，也是首页那句「总得留下点什么吧」的容器，值得单独调好。

建议：边线 3px、内边距 16px。边线变细后视觉重量下降，内边距拉开后文字有呼吸。

P1表格内边距 4px、行内代码 2px —— 纯上游默认值，从未调过

th, td padding: 4px ← 中文单元格里几乎贴边 code padding: 2px ← 左右各 2px，等于没有

这两个值是全站仅存的「上游原封未动」的排版参数。中文没有词间空格， 4px 的内边距让表格读起来像挤在一起的两列字；行内代码的 2px 则让它看起来像被高亮笔涂了一道。

建议：单元格 padding: 8px 10px，行内代码 padding: 1px 5px。

P2日期列 120px，实际内容 91px

.recent-posts { grid-template-columns: 120px 1fr } 日期文字实测宽 ≈ 91px（等宽 15.2px × 10 字符） → 每行浪费 29px，标题列被压到 600px

这是照 yinji.org 逐值对齐的结果，不算错。但 720px 的总宽里白扔 29px， 在手机上（内容区 350px）就等于标题少了 8% 的宽度，是「标题折两行」的直接原因之一。

建议：改成 minmax(92px, auto) 1fr，让日期列贴合内容、又不失对齐。

P2首屏顶部留白 36px，对 720px 的画布偏紧

body padding-top: 20px + h1 margin-top: 16px = 36px

正文宽 720px 的页面，首屏顶部的呼吸通常给 48–64px。36px 会让页头显得「顶在天花板上」， 尤其在桌面端大屏上。

关于「要不要真的引入 CSS 变量」

DESIGN.md 第 7 节写着「别引入 --space-* / --radius-* 这些令牌 —— 它们不存在了」。 那条规矩针对的是上一版自建主题留下的空壳令牌，不是「不许有尺度」。

建议分两步走，避免一次性大改带来的回归风险：

第一步（低风险）：只引入变量定义，把现有硬编码值机械替换成最接近的档位， 每替换一处就截图比对。视觉上应该只有几像素的位移。

第二步（可选）：把 7 个发现里的具体修法落进对应模块。

如果只想做一半 —— 先做 P0 两条。它们占本次收益的七成，且都只有几行代码。

六、不要动的

评审最怕的是「改着改着把好东西改掉了」。下面这些是已经做对、且比大多数同类站点更好的部分：

  • 虚线 hr —— 全站唯一的装饰线条，是这套极简语言里唯一的签名。别换成实线。
  • 正文 1.8 行高 + 28px 段间距 —— 中文长文的正确解，已经是全站最专业的一处。
  • 零外部字体、零 CDN —— 首页 1 个请求、6KB gzip。这个约束比任何视觉优化都值钱。
  • 导航折行用 flex + gap —— 解决了「RSS 从词中间劈开」的真 bug，比上游正确。
  • 代码块配色 —— 逐 token 过 4.5:1，比上游的 monokai 内联色好一个数量级。
  • 元信息对比度 —— 浅色提到 #6e6e6e（5.01:1），修对了上游「浅色比深色还难读」的倒挂。
  • 页脚 4 行结构 —— 你反复调过的行序与分隔符，不动。

需要你拍板的一件事

站名要不要从 32px 降到 24px？

这是本次唯一「会改变站点性格」的改动。降下去之后，文章标题成为页面上最大的元素， 层级立刻清晰、也更接近现代博客的通行比例；代价是站名的存在感变弱，页头整体矮 16px。

三个选项：

  1. 降到 24px（推荐）—— 层级最清晰，改动最小。
  2. 保持 32px，只把文章标题升到 36px —— 不动头部，但两者差距只有 4px，层级改善有限。
  3. 保持 32px 不动 —— 只做 P0-1（首页行距）与 P1 其余各项，接受「品牌与内容同级」。

选完之后我按你选的做，不做你没点的项。
