{{- /* ---------- 正文内链（2026-10-26 新增） ---------------- 问题：133 篇里 120 篇正文零内链（全站正文互链只有 34 条）， 影响 Google 的主题相关性判断。人工挨篇插链接要动 120 个 content 文件 —— 那是用户手写的东西，不动。 方案：**渲染层自动链接**。词表在 `data/inline-links.json` （{a: 锚点字面量, u: 目标 URL}），这里在输出 HTML 上把正文中 出现的锚点词包成 。锚点=目标文章的标题或其核心词，全部 逐字校验过「确实在其他文章正文里出现过」才进词表，共 29 条。 ⚠️ 匹配模式 `>([^<]*)锚点([^<]*)<`：只在**文本节点**里匹配 —— `[^<]*` 不能跨越 `<`，所以属性值（alt、href、og:title 等 meta 全是属性）天然安全。这正是选 .Content（HTML）而不是 .RawContent（Markdown）的原因：Markdown 里无法区分链接 文本和普通文本，HTML 里 `>文字<` 的边界是可靠的。 ⚠️ 同页跳过（`ne $self .u`）：目标文章自己的正文提到自己的 锚点词不链接，也顺带保证不碰它的 （标题含锚点词 的页面恰好就是目标页，跳过后 <title> 永远安全）。 ⚠️ 锚点词先过一遍正则转义（「使用 Mac 5+ 年」的 + 等）； Hugo 没有 escapeRegex，用 strings.ReplaceAll 逐字符转义， **反斜杠必须第一个处理**。 ⚠️ 词表约束：锚点之间**不得互为子串**，否则先替换的会包进 后替换的文本节点，产生嵌套 <a>（生成词表的脚本已校验）。 所以只有 29 条 —— 像《小狗钱钱》这种被别的锚点包含的词 主动放弃了。 ⚠️ 已知盲区（故意接受）：锚点出现在代码块里也会被链接 （构建后有专项审计，应为 0 条）；正文源文件里的 `&` 是 `&`，「我舍不得家 and & or 家乡」这条可能匹配不上， 匹配不上就是没有，不报错。 ⚠️ 改词表不用动这里：往 data/inline-links.json 加 {a, u} 即可，跑一次生成脚本校验子串关系。 */ -}} {{- $c := .c -}} {{- $self := .p.RelPermalink -}} {{- range index hugo.Data "inline-links" -}} {{- if ne $self .u -}} {{- $esc := .a -}} {{- range $ch := (slice "\\" "." "+" "?" "*" "(" ")" "[" "]" "{" "}" "|" "^" "$") -}} {{- $esc = strings.Replace $esc $ch (printf "\\%s" $ch) -1 -}} {{- end -}} {{- /* 守卫：$1 是锚点前面**紧邻的那个标签**。RE2 没有负向断言， 「不是 <a 开标签」只能用标签名规则表达： [^a>][^>]* 标签名不以 a 开头（含 </xxx> 闭标签，/ 不是 a） a[a-zA-Z0-9] 标签名以 a 开头但不止一个字母（abbr/article/aside/audio/area） 于是恰好排除 <a> 和 <a …> —— 锚点在既有链接的可见文字里时 （如 <a href=外链>综述写作之-文献管理</a>），整段不匹配、不嵌套。 没有这条守卫的实测后果：嵌套 <a> 是非法 HTML，minifier 还会 把括号剥歪（rel="noopener noreferrer" <a href=…>…</a>/a>）。 */ -}} {{- $pattern := printf "(<(?:[^a>][^>]*|a[a-zA-Z0-9][^>]*)>)([^<]*)%s([^<]*)<" $esc -}} {{- $repl := printf "$1<a href=\"%s\">%s</a>$2" .u .a -}} {{- $c = replaceRE $pattern $repl $c -}} {{- end -}} {{- end -}} {{- return $c -}}
