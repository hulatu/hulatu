{{- /* Hugo 版本兜底：本机 / GitHub Actions / Cloudflare Pages 三边版本不一致时， 让构建**直接失败并报出当前版本**，而不是悄悄渲染出不对的页面。 为什么不用 hugo.toml 的 [module.hugoVersion] 当唯一手段：实测那个约束在 项目自身配置里只打一行 WARN（"Module project is not compatible with this Hugo version"），构建照样成功，拦不住。所以这里用 errorf 硬拦。 版本是硬拦，extended 只警告：Cloudflare 的 HUGO_VERSION 只能填版本号、没法指定 extended，硬拦有误伤线上的风险；而真要用到 extended 功能（head-meta.html 用 imageConfig 读 share.webp）时，Hugo 自己会报错并停下，不会静默出错。 从 baseof.html 顶部引入，每个页面都会跑一次（版本达标时零输出零开销）。 报错后的处理办法见 README「安装 Hugo（Extended 版本）」。 */ -}} {{- $parts := split hugo.Version "." -}} {{- $major := int (index $parts 0) -}} {{- $minor := int (index $parts 1) -}} {{- $tooOld := and (eq $major 0) (lt $minor 166) -}} {{- if $tooOld -}} {{- errorf "Hugo 版本不达标：本站需要 0.166.0 及以上，当前是 %s。本机请升级 Hugo；Cloudflare Pages 请在项目环境变量里设置 HUGO_VERSION=0.166.0（主站 + 四个子站都要）。" hugo.Version -}} {{- end -}} {{- if not hugo.IsExtended -}} {{- warnf "当前 Hugo 不是 extended 版（%s）。本机建议装 extended；若线上真用到它才有的功能（读 WebP 尺寸等），Hugo 会自己报错，这里不拦构建。" hugo.Version -}} {{- end -}}
