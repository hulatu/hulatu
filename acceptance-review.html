怎么验收这个站的设计

你问的是「怎样验收」。这份页面的答案分两半：上半是方法——一套六层、每层都有可复算判据的检查栈； 下半是这套方法今天真跑一遍的结果。页面末尾给了全部命令，任何一条你都能自己重跑出同样的数字。

本轮做了什么

① 复算了上一轮的四项承诺，4/4 全部落地；② 跑完三段常规扫描 + 两个「死代码」必查项，基本全过； ③ 用真浏览器量了手机档（390px）的触控命中区 —— 这是唯一必须有浏览器的层；④ 得到 4 条发现（2 条 P1、2 条 P2）。

本页不改任何站点代码。它是一份工作产物，采纳之后可以删。

01验收不是「看着还行」

「乱」「挤」「不高级」是线索，不是结论。线索的价值在于它能被翻译成数字 —— 「年行挤了 4 个元素」「末行只有 1 个字」「命中区 36.7px」都是可复算的；「有点挤」不是。 验收做的事就是把前者从后者里逼出来，然后用能被别人重跑的命令证明它。

所以判据要满足两条：有阈值（44px、4.5:1、0 警告）、有复算路径（一条命令、一段脚本）。 做不到这两条的，就别写进验收清单 —— 它会变成谁也没法反驳的口头意见。

02六层验收栈

从「机器一票判定」到「只有你能判」，六层依次是：

01 构建exit 0 · 0 警告 · 页数与内容对得上 机器
02 语义每页恰好 1 个 h1 · 同页 id 不重复 · 标签配平 机器
03 CSS 卫生刻度长尾 · 空章节 · 重复选择器 · 死声明 · 死 token 机器
04 几何断点 · 溢出 · 折行 · 触控命中区 机器 · 要浏览器
05 颜色文字 ≥ 4.5:1 · 层次用 ΔL*，不用 WCAG 机器
06 品味「这个红是不是铺得太多」「这页要不要这么长」 只有你

前三层和后两层都能在命令行里跑完。第 4 层是分水岭：它要一个真的排版引擎 —— getBoundingClientRect() 拿不到的东西（伪元素撑开的命中区、真实的折行位置）只能在那儿量。 第 6 层永远不该由我替你判：我能把「红色铺开的面积」算给你，但「够不够」是你的。

第 5 层有一条反直觉的规矩：谈「浮层浮不起来」要用 CIE 明度 ΔL*，不能用 WCAG 对比度。 深色页面底 #0b0b10 的 L* 只有 3.14，遮罩最多只能把它压暗 3 点 —— WCAG 在近黑区被压得几乎不可分，而 L* 差是眼睛真能看到的。（自检：#ffffff→100.000、#000000→0.000、#808080→53.585。）

05本轮 · 真浏览器实测（手机档 390px）

这是唯一跑不到命令行的层。做法：把构建产物复制一份、往页面尾部注入一段探针， 探针自己滚动取样，用 document.elementFromPoint() 在目标周围打 15×15 个点， 数有多少点真的落在它身上 —— 这直接量的是有效命中区，把伪元素扩展和邻居遮挡都算进去了， 比读 CSS 里的 inset 可靠。

先说结论里好的一面：文档里声称「已撑到 44px」的那几类，实测确实到了 —— .site-brand 30→44、.post-cat-chip / .post-tag-chip 22→44、 .post-toc-inline-head 21→43~44。也就是说「伪元素 + 负 inset」那套手法是真的在生效， 不是写在注释里好看。

06四条发现

P1

翻页按钮的命中区只有 37.8px，而注释声称是 44

critical.css 里写着「视觉 34×34 → 44×44」，实测手机档下有效命中区 37.8px， 少了约 26% 的面积。原因不是扩展器写错了，是被邻居吃掉。

链条是这样的：@media (max-width: 600px) 把 .list-toolbar 改成 justify-content: center，同时把 .home-archive-link 的 margin-left: auto 归零 —— 于是「翻页器」和「查看归档」在手机上紧贴在一起，中间没有 gap。 两边各有扩展器（翻页各扩 5px、「查看归档」各扩约 4.5px），而「查看归档」DOM 顺序在后 → 绘制在上， 压住了翻页按钮右侧那一块。

这正是 DESIGN.md 自己为 .nav-icon-btn 记下的那个坑 —— 当时因为它们「相邻两个的命中区互相重叠 4px」而把扩展去掉了。同样的相邻关系在翻页器这一侧没有被检查过。

改：assets/css/critical.css 的 @media (max-width: 600px) 里给 .list-toolbar 补一个 gap（最省事），或收窄 .pager-btn::after 的横向扩展。

P1

/privacy/ 是全站唯一「有文章版式、却没有长文装置」的页面

全站有 89 页渲染出文章版式（右栏 .post-rail + 目录）， 有 125 页带进度条与返回顶部。这两组里，/privacy/ 是唯一一个「有目录、没装置」的—— 它的 HTML 有 51594 字节、目录 12 项（在 89 个有目录的页面里排第 8）。

原因是上一轮收窄时用的判据是 .Type ∈ {posts, weekly}（按栏目判）， 而 /privacy/ 是根目录下的独立页 —— 它走的是文章模板，但不属于那两个栏目。 这类问题正是「上一轮没做完的」：同一个判断没覆盖到的页面。

改：layouts/_default/baseof.html 的 $longForm 判据，或显式把 privacy 加进去。

P2

DESIGN.md 的「行距封顶」例外清单漏了一整类

DESIGN.md 写着「到不了 44px 的只剩一类，是刻意的」，然后只列了三个： .series-pill（32.5）、.friends-list a（36）、.tag-chip（38）。 实测还有第四类：手机档的目录链接 .post-toc-inline-nav a，310 × 25.4、命中区 36.7–41。

判据本身没问题 —— 它和那三个是同一类（会换行的密列表，命中区上限由行距决定，靠 WCAG 2.5.5 的 Spacing 例外过关，硬撑到 44 反而会让相邻两行互相吃）。问题是清单不完整： 下次有人照这份清单核对，会以为目录链接是漏了。

改：DESIGN.md 的「触控命中区」一节，把这一类补进例外表。

P2

.site-header 的 transition 里有一条永不触发的 box-shadow

critical.css 的 .site-header 声明了三条过渡： background、box-shadow、transform。 但全站没有任何规则给 .site-header 设过 box-shadow —— background 有、transform 有（.is-hidden 那个 translateY(-100%)）， box-shadow 没有。

它是 2026-10-02「去玻璃」那次改动的残留：当时把投影删了、换成了滚动时出现的一条 1px 底线 （.nav-container::after），但过渡词表没跟着删。

改：assets/css/critical.css 第 436 行，去掉 box-shadow … 那一段。
