P1搜索面板的 ARIA 只做了一半

改：assets/js/search.js（约 573–602 行 + 95 行输入框）

搜索是全站最复杂的交互，作者也确实在认真处理 ARIA —— search.js:98 有一条注释解释了「为什么不给外层挂 role="listbox"」， 焦点陷阱、aria-label、aria-pressed 都齐。但结果列表这一层缺了状态同步：

应有现状后果
aria-selected 在选中项上缺 setActive() 只 classList.add("is-active")，屏幕阅读器不知道 ↑↓ 移到了哪一条
输入框 role="combobox" + aria-expanded + aria-controls 缺listbox 与输入框没有任何 ARIA 关联
aria-activedescendant缺 焦点留在输入框里，选中项不会被朗读
role="option" 挂在哪 挂在 <a> 上 覆盖掉了链接语义 —— role="option" 会让 AT 不再把它当链接读

视觉与键盘用户完全不受影响（↑↓ / Enter / Esc 都能用），所以这是 P1 不是 P0。 修法很小：setActive() 里同步 aria-selected， 输入框补三个属性，role="option" 移到内层 <span> 或改成 role="option" + 保留 <a> 的导航职责（二选一，见结尾问题）。

目录在宽屏是右侧刻度栏、窄屏是正文开头那块，共用 .post-toc-nav 这个类。 10-09 那次改的是刻度栏那一份，于是两边的「我在哪」现在长得不一样：

多出来的 font-weight: 600 会把当前行拉宽。 这份内联目录默认是收起的（initInlineToc()），所以只有用户手动展开时才会看到， 但那一刻它比刻度栏「响」一倍。

P2刻度栏窗口首次定位会「从第 1 行滑过去」

改：assets/js/toc.js（placeRailWindow）+ assets/css/critical-post.css:586

这是 10-09 那次改动自己带进来的。事实链：

环节事实
CSS 默认值translateY(var(--toc-shift, 0px)) → 初始 0
0 意味着窗口对准目录第 1 行
过渡transition: transform var(--dur-base) var(--ease) —— 无条件生效
JS 写入时机defer 脚本的 DOMContentLoaded → sync() → setActive() → aimRailWindow()

于是从搜索结果或别人的链接带着 #锚点落到文章中段时，收起态的窗口一定是 「先显示第 1 行，再用 0.22s 滑到当前行」。滑到正确位置是好的（那正是「日历翻页」的手感）， 但第一次定位不该有动画 —— 它不是「翻页」，是「落位」。

修法很小：给 .post-rail 加一个 is-ready 类，首次 placeRailWindow() 之后再打上；CSS 把 transition 挂到 .post-rail.is-ready .post-toc-nav 上。这样 mouseleave 那次的回位动画照旧。

03不建议加，以及为什么（必答项）

这一节是为了让下一轮不用重新论证一遍。前面几轮里试过又被否掉的，也在这一节。

项裁决依据
Now 页 /now/不加 2026-10-08 用户拍板删的，连文件带导航一起撤。footer.html 与 index.html 的注释都留了「⚠️ 别再加回来，页面已经不存在」。 （~/bearneo-trial 是另一个站，那边加过不影响这里。）
文末「赞一下」/「引用本文」不加 2026-10-08 新增，同日按用户要求移除。落点在 partials/post-kudos.html + partials/post-cite.html + critical-post.css 末两段 + ui.js。要加回来是四处一起补。
文末「上一篇 / 下一篇」（按时间）不加 2026-10-05 整条移除。它原先与「相关文章」是 if/else 互斥，而 124 篇里没有一篇算不出相关文章 —— 那一支从没亮过。要「按顺序连载」走 series（即上面那条 P0）。
点赞 / Kudos不加 bearneo 唯一真需要后端的（Cloudflare Workers + D1），工程量过夜、收益不确定。
Mermaid 图表不加 content/ 里命中 0 处，加了就是死代码。
字号调节 / 阅读模式不加 浏览器本身就有缩放；自建一套等于再维护一份排版真相。
邮件订阅不加 要第三方服务与地址托管；RSS 全文已经开着。
bearneo 的纯 CSS 图片放大不搬 input[type=checkbox] + 双 <label>，连 Esc 都关不掉。 本博客的 JS 灯箱 + 真 <a href="原图"> 更好。
hr 改成虚线不搬 本博客「40% 宽 + 印章红圆点」是签名。
text-wrap: balance / pretty不加 Level 4 这批特性设计目标几乎都是英文场景，中文里表现为行提前换行 —— 正是「断开的地方没到最右端」这个症状。
text-spacing-trim / font-feature-settings:"halt"加不了 硬约束：Songti SC 连 GSUB 表都没有，PingFang SC 也没有 halt/chws —— 属性会被浏览器静默禁用。写了比不写更糟。

需要你拍板的一件事

P0 那条「系列带」的形态，我不替你决定。三种做法代价不同，选一个我再动手：

  • 方案 A 文末一条「系列 · 综述写作 · 第 2 / 5 篇」+ 系列内上一篇 / 下一篇两行。 最省事，只动 single.html 与一段 CSS；位置在「完」印章与「相关文章」之间。
  • 方案 B 在 A 的基础上，把整个系列 5 篇都列出来（像归档页那排胶囊，当前篇高亮）。 读者一眼看到全貌，但文末会多出 1–3 行；跑步那组 12 篇会明显变长，需要折叠。
  • 方案 C 不放在文末，放在文章标题下面的面包屑旁，只写「系列 · 第 2 / 5 篇」（可点开看全部）。 位置更早、更显眼，但要碰 single.html 的头部区与面包屑那条线语言。

另外 P1 的搜索 ARIA 有个小选择：role="option" 是移到内层 span（保住 <a> 的链接语义， 但 listbox 的键盘模型就不完全标准），还是保留在 <a> 上并补全 aria-selected / aria-activedescendant（ARIA 完全合规，代价是 AT 不再把它当链接读）。 我倾向后者 —— 那个列表本来就是「选一个然后跳走」的 listbox 语义。你不特别说的话我就按后者做。
